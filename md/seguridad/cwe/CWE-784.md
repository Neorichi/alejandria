# CWE-784: Reliance on Cookies without Validation and Integrity Checking in a Security Decision

**Tipo de fallo de software CWE-784** (Variant).

The product uses a protection mechanism that relies on the existence or values of a cookie, but it does not properly ensure that the cookie is valid for the associated user.

- **Es un caso de:** [CWE-807](/seguridad/cwe/CWE-807.md), [CWE-565](/seguridad/cwe/CWE-565.md)

## Consecuencias

- Bypass Protection Mechanism: It is dangerous to use cookies to set a user's privileges or perform other security-critical actions. Attackers can easily modify cookies, within the browser or by implementing the client-side code outside of the browser. The cookie can be manipulated to claim a high level of authorization, or to claim that successful authentication has occurred.

## Cómo evitarlo

- Avoid using cookie data for a security-related decision.
- Perform thorough input validation (i.e.: server side validation) on the cookie data if you're going to use it for a security related decision.
- Add integrity checks to detect tampering.
- Protect critical cookies from replay attacks, since cross-site scripting or other attacks may allow attackers to steal a strongly-encrypted cookie that also passes integrity checks. This mitigation applies to cookies that should only be valid during a single transaction or session. By enforcing timeouts, you may limit the scope of an attack. As part of your integrity check, use an unpredictable, server-side value that is not exposed to the client.
