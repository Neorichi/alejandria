# CWE-617: Reachable Assertion

**Tipo de fallo de software CWE-617** (Base).

The product contains an assert() or similar statement that can be triggered by an attacker, which leads to an application exit or other behavior that is more severe than necessary.

- **Es un caso de:** [CWE-705](/seguridad/cwe/CWE-705.md), [CWE-670](/seguridad/cwe/CWE-670.md)

## Consecuencias

- DoS: Crash, Exit, or Restart: While assertion is good for catching logic errors and reducing the chances of reaching more serious vulnerability conditions, an attacker can still cause a denial of service if they can trigger an assert statement, and if the scope of the assert() extends beyond the attacker's own session. For example, if a server handles multiple simultaneous connections, if an assert() occurs in one single connection that causes all other connections to be dropped, this could be a significant denial of service.

## Cómo evitarlo

- If the assertion statement is required (e.g., for security or reliability), change the invoking code to avoid the conditions that trigger the assertion.
- Consider changing the assertion to some other less "fatal" error. This might not be easy to implement, since other code may be needed to handle the error.
- Make sensitive open/close operations non-reachable from directly user-controlled data (e.g. open/close resources)
- Perform input validation on user data.
